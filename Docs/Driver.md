# MagicAAP 驱动安装与故障排查

> **免责声明**：MagicAAP 驱动由 [MagicPods](https://magicpods.app) 项目提供，本应用（AirPodsWindows）
> 仅依赖其接口，不包含、不修改也不重新分发该驱动。MagicAAP 与 MagicPods 为其各自所有者的第三方
> 商标，本文档只引用官方链接，不代表任何背书或从属关系。

## 1. 概述

MagicAAP 是一个 Windows 驱动，为 AAP（Apple Accessory Protocol）通道提供用户态接口。本应用中
所有需要走 AAP 通道的功能（降噪控制、对话感知等）都通过该驱动完成；电池、弹窗、入耳检测等走
BLE 广播通道的功能与驱动无关，未安装驱动时照常工作。

**驱动解锁的能力**（官方口径）：

- 降噪控制
- 精确电量
- 按键定制
- 增强耳检测
- 对话感知
- 可访问性设置

**支持型号**：全系 AirPods + Beats。

**版本信息**：驱动版本 `0.0.0.1`（2024-06-06）。

**应用侧要求**：MagicPods ≥ `2.0.72.0`。

本应用设置页的「驱动状态卡」显示当前驱动状态，四种状态与本文档[故障排查](#6-故障排查)表一一对应。

### 两条安装路径对比

| | 路径 A：官方未签名版 | 路径 B：社区签名版 |
| --- | --- | --- |
| 安装方式 | 关闭 Secure Boot + 开启测试签名 + 手动安装 INF | 一条一键命令 |
| 便捷性 | 较繁琐（需进 UEFI、重启） | 便捷 |
| 长期有效性 | **长期有效** | **有时效风险**（见路径 B 的时效警告） |
| 主要代价 | 系统处于测试签名模式 | 需临时关闭 Windows Defender 实时保护 |

## 2. 安装前须知

1. **MagicPods ≥ 2.0.72.0**：驱动依赖该版本（或更新）的 MagicPods 环境。
2. **系统要求**：Windows 10 1809+ 或 Windows 11，x64（与本应用一致）。
3. **备份**（无论选哪条路径都建议做；路径 A 为必做项）：
   - 创建一个**系统还原点**（`系统属性` → `系统保护` → `创建`）；
   - 备份 **BitLocker 恢复密钥**（确认已保存到 Microsoft 账户）。路径 A 关闭 Secure Boot 后，
     BitLocker 会在下次启动时要求输入恢复密钥，没有备份会导致数据无法访问。
4. **备份现有驱动状态**：记下设备管理器中当前蓝牙/音频设备状态，便于回退。

## 3. 路径 A：官方未签名版（长期有效，代价高）

未签名驱动需要系统开启测试签名模式才能加载，因此要动 UEFI 设置。一次配置后长期有效，
不依赖任何第三方签名服务的存续。

### 步骤 1：创建系统还原点并备份 BitLocker 恢复密钥

见[安装前须知](#2-安装前须知)第 3 条。跳过此步的风险由你自己承担。

### 步骤 2：关闭 Secure Boot

重启进入 UEFI 设置（开机按 `Del`、`F2`、`F12` 等键，视主板而定），在 `Security` 或
`Boot` 菜单中将 **Secure Boot** 设为 `Disabled`，保存退出。

> 部分品牌机（尤其预装 Windows 11 的机型）关闭 Secure Boot 前需要先清除已有密钥或设置
> 管理员密码，具体以主板/机型手册为准。

### 步骤 3：开启测试签名模式

以**管理员身份**打开 PowerShell，执行：

```powershell
bcdedit /set testsigning ON
```

重启计算机。重启后桌面右下角可能出现「测试模式」水印，属正常现象。

> 测试签名模式会放宽内核驱动加载限制，安全性低于默认配置。仅在需要加载未签名驱动期间保持
> 开启，卸载驱动后请按[卸载与还原](#7-卸载与还原)关闭。

### 步骤 4：安装驱动

右键 `MagicAAP.inf` → `安装`。驱动版本为 `0.0.0.1`（2024-06-06）。

### 步骤 5：校验安装包

官方包 SHA256（示例格式，维护者本机核对值，与 magicpods.app 公布值一致）：

```
E16A8F1C…B66C2
```

完整 64 位哈希**以官网公布的校验值为准**；本文档不记录未经可靠来源核实的完整值。

## 4. 路径 B：社区签名版（便捷，有时效风险）

社区签名版通过签名服务加载，无需关闭 Secure Boot、无需开启测试签名，一条命令即可完成；
代价是它依赖签名服务与驱动策略，存在时效风险（见下文警告）。

### 步骤 1：临时降低 Defender 防护

安装期间需要临时关闭 Windows Defender 实时保护，并将 DriverStore 加入排除项：

1. `Windows 安全中心` → `病毒和威胁防护` → `实时保护`，临时关闭；
2. 在同一页面的 `排除项` 中，添加 `C:\Windows\System32\DriverStore`。

### 步骤 2：执行一键命令

以**管理员身份**打开 PowerShell，执行：

```powershell
irm "https://magicpods.app/utils/magicaap-community-v1.ps1" | iex
```

### 步骤 3：恢复 Defender 防护

安装完成后立即重新开启实时保护，并移除第 1 步添加的排除项。

> [!WARNING]
> **时效警告**：2026-04 Windows 安全更新发布后，该社区签名驱动可能出现**无法加载**的情况。
> 如果驱动已安装却加载失败（设备管理器报代码 52 或类似签名错误），在**管理员 PowerShell** 中运行：
>
> ```powershell
> CiTool.exe --remove-policy "{8F9CB695-5D48-48D6-A329-7202B44607E3}"
> ```
>
> 该命令移除针对本驱动的驱动策略；执行后请**保持该策略处于禁用状态**，不要重新启用。

## 5. 功能对照表

**需要驱动的功能 = 一切走 AAP 通道的功能；不需要驱动的功能 = 走 BLE 通道的功能。**

| 功能 | 需要 MagicAAP 驱动 | 通道 |
| --- | :---: | --- |
| ANC 控制（关闭 / 降噪 / 通透 / 自适应） | ✅ | AAP |
| 对话感知 | ✅ | AAP |
| 个性化音量 | ✅ | AAP |
| 响亮声音降低 | ✅ | AAP |
| 自适应强度 | ✅ | AAP |
| PPE 上限 | ✅ | AAP |
| 电量显示 | ❌ | BLE |
| 开盖弹窗动画 | ❌ | BLE |
| 入耳检测自动暂停 | ❌ | BLE |
| 快速连接 | ❌ | BLE |
| 任务栏电量 | ❌ | BLE |

即使不安装驱动，上表中标 ❌ 的功能也全部可用；驱动只影响标 ✅ 的部分。

## 6. 故障排查

下表与应用内驱动状态卡的四个状态一一对应：

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 状态卡显示「未安装」 | 驱动未安装 | 按[路径 A](#3-路径-a官方未签名版长期有效代价高)或[路径 B](#4-路径-b社区签名版便捷有时效风险)之一安装 |
| 已安装但无法加载（设备管理器报代码 52 或类似签名错误） | 2026-04 Windows 安全更新引入的驱动策略问题 | 管理员 PowerShell 运行 `CiTool.exe --remove-policy "{8F9CB695-5D48-48D6-A329-7202B44607E3}"`，并保持该策略禁用 |
| 驱动在但应用显示「已连接（其他通道）」 | 驱动被禁用或相关服务未启动 | 打开设备管理器，检查 MagicAAP 设备状态（是否被禁用、是否有错误代码），必要时启用设备或重启服务 |
| ANC 菜单灰色 / 不可用 | 驱动未就绪，或耳机不支持 ANC | 先确认驱动状态卡；若驱动正常，则属机型限制——仅 AirPods Pro / AirPods Max / AirPods 4（ANC 版）支持 ANC |

补充检查顺序：

1. 状态卡是不是「未安装」→ 先装驱动；
2. 已安装但加载失败 → 查设备管理器错误码，代码 52 走 `CiTool` 命令；
3. 驱动正常但功能仍不可用 → 确认耳机型号是否支持 ANC，再确认 MagicPods ≥ 2.0.72.0。

## 7. 卸载与还原

### 路径 A 的还原

关闭测试签名模式（管理员 PowerShell）并重启：

```powershell
bcdedit /set testsigning OFF
```

- 如之前关闭了 Secure Boot，在 UEFI 设置中重新启用；
- 如创建了系统还原点，可在 `系统属性` → `系统保护` 中执行系统还原。

### 卸载驱动

- 图形界面：`设备管理器` → 找到 MagicAAP 设备 → 右键 `卸载设备`，勾选「尝试删除此设备的驱动程序」；
- 命令行：先用 `pnputil /enum-drivers` 找到 MagicAAP 对应的 `oemXX.inf`，再执行：

```powershell
pnputil /delete-driver oemXX.inf /uninstall /force
```

### 路径 B 的还原

- 重新开启 Windows Defender 实时保护；
- 移除安装时添加的排除项：

```powershell
Remove-MpPreference -ExclusionPath "C:\Windows\System32\DriverStore"
```

- 通过 `CiTool` 移除的驱动策略保持禁用即可，卸载驱动后无需恢复。
